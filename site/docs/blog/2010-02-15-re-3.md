Re: 3.0y (<a href="http://xdelta.googlecode.com/files/xdelta3.0y.tar.gz">source</a>)<br /><del>Re: 3.0x (<a href="http://xdelta.googlecode.com/files/xdelta3.0x.tar.gz">source</a>)</del><br /><br />Version <del>3.0x</del> 3.0y fixes several regressions introduced in 3.0w related to the new support for streaming the source file from a FIFO.  This was a long-requested feature and I'm pleased to report that now, with the fixes in <del>3.0x</del> 3.0y, it appears to be working quite well.  The upshot of this feature is that you can encode or decode based on a compressed source file, without decompressing it to an intermediate file.  In fact, you can expect the same compression with or without a streaming source file.<br /><br />There were also reports of the encoder becoming I/O bound in previous releases, caused by the encoder improperly seeking backwards farther than the settings (namely, the -B flag) allowed.  This is also fixed, and there's a new test to ensure it won't happen again.<br /><br />Windows users: I need to investigate issue <a href="http://code.google.com/p/xdelta/issues/detail?id=101">101</a> before building a release of<del>3.0x</del> 3.0y.  Until I can confirm that streaming-source-file support works on Windows, please continue using the 3.0u release.<br /><br /><del><b>Update:</b> The built-in support for automatic decompression of inputs is interacting badly with the new source handling logic, results in <a href="http://code.google.com/p/xdelta/issues/detail?id=106">poor compression</a>.</del>
