Re: 3.0w (<a href="http://xdelta.googlecode.com/files/xdelta3.0w.tar.gz">source</a>)<br /><br />With such a good state of affairs (i.e., no bug reports), I was able to tackle a top-requested feature (<a href="http://code.google.com/p/xdelta/issues/detail?id=59">59</a>, <a href="http://code.google.com/p/xdelta/issues/detail?id=73">73</a>).  Many of you have asked to be able to encode deltas using a FIFO as the source file, because it means you can encode/decode from a compressed-on-disk source file when you don't have enough disk space for a temporary uncompressed copy.  This is now supported, with one caveat.<br /><br />When decoding with a non-seekable source file, the -B flag, which determines how much space is dedicated to its block cache, must be set at least as large as was used for encoding.  If the decoder cannot proceed because -B was not set large enough, you will see:<br /><br /><b><tt>xdelta3: non-seekable source: copy is too far back (try raising -B): XD3_INTERNAL</tt></b><br /><br />The stream->src->size field has been eliminated.  Internally, a new stream->src->eof_known state has been introduced.  This was a big improvement in code quality because, now, the source and target files are treated the same with respect to external (de)compression and several branches of code are gone for good.<br /><br /><b>Update</b> Issue 95: <a href="http://code.google.com/p/xdelta/issues/detail?id=95">command-line decode I/O-bound in 3.0w</a>
